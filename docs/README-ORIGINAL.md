# افهمها — المنصة + الباك اند

واجهة افهمها الأصلية (HTML/JS) كما هي، ومعها الآن **خادم Node.js + Express + SQLite** يوفّر:

- حسابات حقيقية (تسجيل/دخول/خروج، كلمات مرور مُشفّرة bcrypt، جلسة بكوكي HttpOnly) مع اشتراك سنوي وموافقة أدمن قبل فتح المحتوى.
- حفظ تقدم كل طالب على السيرفر ومزامنته بين الأجهزة (الدروس المكتملة، آخر موضع قراءة، التقييم، نتائج الاختبارات، دفتر الأخطاء…).
- المحتوى (المنهج/الدروس/الاختبارات/فهرس البحث) محفوظ في قاعدة البيانات، ولا يُقدَّم إلا لحساب أدمن أو طالب لديه اشتراك نشط.
- لوحة إدارة عبر API وصفحة مراجعة اشتراكات: فحص إثباتات الدفع، الموافقة أو الرفض بسبب، وإدارة المحتوى والمستخدمين.

## التشغيل

```bash
npm install   # يلزم Node.js 22.13 أو أحدث
npm start          # http://localhost:8000
```

أول تشغيل ينشئ قاعدة البيانات، ويحمّل المنهج من `server/seed/`، وينشئ حساب المسؤول
(`admin@efhama.local` + كلمة مرور عشوائية تُطبع في الطرفية مرة واحدة، أو حدّدها بـ `ADMIN_EMAIL` / `ADMIN_PASSWORD`).

```bash
npm test                  # اختبارات API والاشتراكات
npm run seed -- --force   # إعادة تحميل المحتوى من server/seed (يستبدل المحتوى الحالي)
npm run reset-admin       # استعادة/إنشاء حساب المسؤول عند تعذّر الدخول
```

الإنتاج: انسخ `.env.example`، وعيّن `NODE_ENV=production` و`JWT_SECRET` (إلزامي)، واضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD`، وضع `DB_PATH` على قرص دائم مع نسخ احتياطية. استخدم HTTPS (الكوكي `Secure` في الإنتاج). تحفظ صور الإثبات كبيانات BLOB داخل SQLite، لذا يلزم تخزين دائم للقاعدة ونسخها احتياطيًا.

## التسجيل والاشتراك

تبدأ الحسابات الجديدة من `register.html`، قبل إنشاء الحساب تعرض الصفحة الاشتراك الوحيد **100 EGP / Year** لمدة 12 شهرًا، وبيانات التحويل من الإعداد المركزي `public/js/payment-config.js`. يجب رفع صورة PNG أو JPEG أو WebP صالحة لا تتجاوز 5 MiB. تُفحص الصيغة والحجم في الخادم وتُحفظ الصورة في قاعدة البيانات ولا تُتاح إلا للأدمن. لا يوجد ربط تلقائي بمزود دفع؛ على المسؤول التحقق من التحويل يدويًا قبل الموافقة.

ينشئ الطلب حسابًا بحالة `pending`، ولا يستطيع المستخدم تسجيل الدخول قبل موافقة الأدمن. يمكنه إدخال بريده وكلمة مروره في صفحة التسجيل للتحقق من حالة الطلب؛ لا يعيد الخادم السبب أو الحالة إلا بعد التحقق من كلمة المرور. عند الرفض يظهر السبب ويسمح بإعادة إرسال الإثبات. موافقة الأدمن وحدها تغيّر حالة الحساب إلى `active` وتفعّل الاشتراك. الاشتراك يبدأ عند الموافقة وينتهي بعد سنة تقويمية، وتمنع الخوادم المحتوى بعد انتهاء الصلاحية. حواجز الاشتراك تشمل صفحات HTML وواجهات المحتوى وحالة الطالب والتحديات والاختبارات، كما لا يخزن Service Worker صفحات أو بيانات المحتوى المدفوع.

يسمح النظام بجلسة نشطة واحدة لكل حساب، ولا يربط الحساب بجهاز مادي ثابت. عند محاولة الدخول من متصفح آخر، تظهر للمستخدم نافذة لتأكيد نقل الجلسة أو إلغائها. يتطلب النقل تأكيدًا صريحًا، وكلمة المرور، ورمز تحدٍ قصير العمر محفوظًا بصيغة Hash في قاعدة البيانات. عند نجاحه تُدوّر الجلسة النشطة ويُبطَل رمز الدخول السابق على الخادم فورًا؛ الطلبات المحمية من الجلسة السابقة تُرفض، والصفحات المفتوحة تعيد التحقق من الجلسة كل 15 ثانية. عمليات النقل ونتائجها تظهر في سجل الإدارة. يعتمد التعرف على امتلاك كوكي HttpOnly آمنة، لا على IP أو User-Agent ولا على بصمة مادية للجهاز.

الحسابات الموجودة قبل هذا التغيير لا تُمنح اشتراكًا افتراضيًا ولا تُحذف بياناتها. يمكنها تسجيل الدخول ثم إرسال طلب اشتراك من صفحة التسجيل. لا يُحذف أي مستخدم أو تقدّم عند ترقية مخطط SQLite؛ تنشأ جداول الاشتراك والجلسات الناقصة تلقائيًا عند بدء الخادم. إذا كانت قاعدة البيانات من إصدار ربط الأجهزة السابق، تبقى أعمدة وسجلات الجهاز القديمة كما هي ولا تُستخدم لاتخاذ قرار السماح بالدخول.

## البنية

```
public/            الواجهة (تُقدَّم كملفات ثابتة) — تصميمها لم يتغير
  js/auth.js       الحساب + طبقة المزامنة (التعديل الجوهري الوحيد، مع login.html/js و service-worker.js)
server/
  seed/            محتوى المنهج الأصلي (JSON) — يُحمَّل في القاعدة مرة واحدة
  src/             index.js (التطبيق) · db.js (الجداول) · auth.js · content.js · seed.js
  src/routes/      auth · content · state · admin
  test/api.test.js
```

## كيف تعمل المزامنة بدون تغيير صفحات الواجهة؟
الصفحات ما زالت تقرأ وتكتب في `localStorage` بنفس المفاتيح (`efhama_completed` …).
`js/auth.js` يعترض الكتابة على المفاتيح المعروفة فقط ويرفعها للخادم بعد نصف ثانية (وعند إغلاق الصفحة)،
وعند فتح أي صفحة يجلب حالة الحساب. عند أول دخول يُضم تقدم الجهاز القديم مع الحساب.
لو انقطع الاتصال تبقى التغييرات معلّقة وتُرفع لاحقًا. عند الخروج يُمسح تقدم الحساب من الجهاز.

## الإنجازات وXP
نظام Gamification في مسارات البرمجة يعيد استخدام إكمال الدروس ونتائج الاختبارات والتحديات والمشروعات الموجودة. تُسجل المكافآت مرة واحدة لكل إنجاز في `localStorage` بالمفتاح `efhama_gamification_v1`، وتُضبط قيم XP والمستويات وشروط الشارات في `public/programming-paths/gamification-config.js`.

سجل Gamification الحالي محلي على الجهاز والمتصفح، ولا تتم مزامنته بين الأجهزة أو الحسابات. يمكن تعديل بيانات المتصفح محليًا؛ لذلك لا يُعد هذا النظام وسيلة لمنع التلاعب أو سجلًا موثوقًا للخادم. لا تُمنح النقاط عند فتح المحتوى، بل عند تسجيل الإكمال أو الاجتياز في التدفقات التعليمية الفعلية.

## الـ API (كلها JSON، والجلسة بكوكي)

| المسار | الوصف |
|---|---|
| `POST /api/auth/register` `{name,email,password,confirmPassword,proof,remember}` | إنشاء حساب وطلب Pending مع صورة إثبات؛ لا يمنح المحتوى |
| `POST /api/auth/login` `{email,password,remember}` | دخول للحساب المعتمد؛ إذا كانت هناك جلسة أخرى فعالة يرجع `409 active_session` ورمز تأكيد قصير العمر |
| `POST /api/auth/login/transfer` `{email,password,remember,transferToken}` | تأكيد نقل الجلسة؛ يبطل الجلسة السابقة ويبدأ الجديدة ذريًا |
| `POST /api/auth/login/cancel-transfer` `{transferToken}` | إلغاء طلب النقل والإبقاء على الجلسة الحالية |
| `POST /api/auth/logout` · `GET /api/auth/me` · `GET /api/auth/config` | |
| `GET /api/auth/subscription` | حالة اشتراك الحساب وآخر طلب وسبب الرفض |
| `POST /api/auth/subscription-status` `{email,password}` | التحقق من حالة الطلب وسبب الرفض دون تسجيل دخول؛ يتطلب كلمة المرور |
| `POST /api/auth/subscription-request` `{name,proof}` | إرسال أو إعادة إرسال إثبات لحساب مسجل |
| `POST /api/auth/change-password` | يبطل رموز الدخول السابقة ويجدد الجلسة الحالية |
| `GET /api/curriculum` · `/api/lessons/:id` · `/api/quizzes/:chapter` · `/api/search-index` | المحتوى (يتطلب اشتراكًا نشطًا أو صلاحية أدمن). نفس البيانات على مسارات `/data/...` التي تستخدمها الواجهة |
| `GET /api/state` | كل حالة الطالب `{state:{key:value}}` |
| `PUT /api/state/:key` `{value}` · `PUT /api/state` `{items:{...}}` · `DELETE /api/state/:key` | حفظ الحالة (مفاتيح معروفة فقط، مع تحقق من القيم) |

**المسؤول** (`role=admin`):

| المسار | الوصف |
|---|---|
| `GET /api/admin/stats` | عدد الطلاب، النشطون آخر 7 أيام، إكمال وتقييم كل درس، متوسط نتائج الاختبارات |
| `GET /api/admin/users?q=&limit=&offset=` | قائمة المستخدمين |
| `GET /api/admin/subscription-requests?status=pending\|approved\|rejected` | طلبات الاشتراك وحالتها وتواريخ التفعيل |
| `GET /api/admin/subscription-requests/:id/proof` | إثبات دفع خاص يتطلب صلاحية أدمن |
| `POST /api/admin/subscription-requests/:id/approve` | موافقة وتفعيل الاشتراك لمدة سنة تقويمية |
| `POST /api/admin/subscription-requests/:id/reject` `{reason}` | رفض الطلب مع سبب ظاهر لصاحبه |
| `GET /api/admin/session-transfers` | سجل محاولات النقل ونتائجها وبيانات السياق للمراجعة |
| `PATCH /api/admin/users/:id` `{role,active,name}` | تغيير الدور / تعطيل (يُنهي جلساته) |
| `POST /api/admin/users/:id/reset-password` `{password}` · `DELETE /api/admin/users/:id` | |
| `PUT /api/admin/curriculum` · `/lessons/:id` · `/quizzes/:chapter` | تعديل المحتوى بنفس صيغة ملفات JSON (انظر `FRONTEND_README.md`) مع تحقق، ويُعاد بناء فهرس البحث تلقائيًا |

## الأمان
- الجلسة في كوكي `HttpOnly` + `SameSite=Lax` (+`Secure` في الإنتاج)؛ تُبطَل عند تغيير كلمة المرور أو تعطيل الحساب.
- لا يُقبل تسجيل الدخول قبل موافقة الإدارة، وتضمن قاعدة البيانات وجود جلسة نشطة واحدة. أثناء النقل، تعيد قاعدة البيانات فحص الجلسة المتوقعة داخل معاملة حصرية، لمنع قبول تأكيدات متزامنة أو مكررة.
- تحديد معدل لمحاولات الدخول/التسجيل، ومقارنة كلمة مرور بزمن متساوٍ حتى لا يُكشف وجود البريد.
- تُستخدم كلمة المرور كما كُتبت؛ المسافات في بدايتها أو نهايتها لا تُحذف تلقائيًا.
- صفحات HTML والمحتوى لا تُقدَّم دون اشتراك نشط (عدا صفحات التسجيل والدخول، مع تجاوز الأدمن). انتهاء الصلاحية يُفحص على الخادم في كل طلب محمي.
- صور الإثبات تُخزن خارج مجلد الملفات العامة، مع فحص الحجم والامتداد المعلن وبصمة تنسيق PNG/JPEG/WebP، وتُعرض عبر مسار يتطلب أدمن.
- helmet (CSP وغيرها)، وحدود لحجم الطلبات والقيم.

موافقة الدفع يدوية ولا تتحقق آليًا من التحويل البنكي. الحماية تمنع الطلبات الجديدة للمحتوى بعد انتهاء الاشتراك، لكنها لا تستطيع محو محتوى سبق أن شاهده المستخدم أو صُوّر/نُسخ من جهازه.

## لم يُبنَ بعد (اقتراحات)
- استرجاع كلمة المرور بالبريد (يحتاج خدمة بريد).
- PostgreSQL لو كثُر المستخدمون جدًا؛ SQLite (المدمجة في Node) تكفي لآلاف الطلاب على خادم واحد.


## المحاضر الصوتي الذكي (مجاني قدر الإمكان)
- في صفحة كل درس يوجد قارئ صوتي يستخدم Speech Synthesis المدمج في المتصفح، بلا تكلفة API. جودة/توافر الصوت العربي تختلف حسب الجهاز والمتصفح.
- يمكن طرح أسئلة نصية، كما يمكن السؤال بالميكروفون في المتصفحات الداعمة لـ Web Speech Recognition.
- بدون مفتاح AI، يبحث المساعد في أقسام الدرس ويرجع الأجزاء الأقرب للسؤال؛ هذا وضع محلي وليس نموذجًا توليديًا.
- لتفعيل إجابات AI التوليدية، أنشئ مفتاحًا من Google AI Studio وفق شروط وحدود الخطة المجانية الحالية، ثم أضفه في متغير البيئة `GEMINI_API_KEY` على الخادم فقط. لا تضع المفتاح في ملفات `public/` أو كود المتصفح. عند تعذر الخدمة يعود التطبيق تلقائيًا للوضع المحلي.
- حدّ الطلبات مضبوط مبدئيًا على 12 طلبًا في الدقيقة لكل عنوان IP.

## استعادة حساب المسؤول
في نسخة جديدة بلا قاعدة بيانات قديمة، شغّلي `npm run reset-admin` لإنشاء حساب المسؤول لأول مرة. في مشروع يحتوي مسؤولًا بالفعل، يعيد الأمر تعيين كلمة مروره. ستظهر قاعدة البيانات المستخدمة، ثم يُطلب البريد (اضغطي Enter لاستخدام `admin@efhama.local`) وكلمة مرور جديدة مرتين. لا تشاركي كلمة المرور مع أي شخص.

## استعادة كلمة مرور المسؤول على Windows

نفّذي `npm install` ثم `npm run reset-admin`. تستخدم الأداة PowerShell لإدخال كلمة المرور دون إظهارها، وتتحقق من نجاح تحديث حساب المسؤول قبل إغلاقها. تفاصيل الخطوات في `RESET-ADMIN-WINDOWS.txt`.
